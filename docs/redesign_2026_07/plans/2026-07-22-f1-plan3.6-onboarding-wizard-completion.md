## Acceptance criterion mapping

- **AK-1:** Solar step is real rendered form, not a static message.
- **AK-2:** Step-2 test button runs a real forecast request, shows result/error.
- **AK-2b:** `/solar_test` has bounded latency; timeout classified as API error.
- **AK-3:** Pricing step is renderable with bundled snapshot, prefill + stale warning, confirm flow.
- **AK-4:** Onboarding state is persisted to `/onboarding` on step transitions and finish; reload restores state.
- **AK-5:** Wizard remains soft guide; no dashboard gate introduced.

## Must-Have / Must-NOT-Have table

### Must-Have
- `STEP_SOLAR` and pricing steps render actual controls in UI DOM (not placeholder text).
- Solar fields come from `STEP_SOLAR.visibleFields()` + same registry source used by settings.
- Step-2 `[Otestovat]` sends real request to `/{box}/solar_test` and renders success/error.
- Step-2 timeout path is bounded and shows a classified error, not a hang.
- Step-3 uses `/pricelists` bundled snapshot only; stale warning shown when `year` is old.
- `/onboarding` stores step `done/skipped`, `timestamps`, and `provider` on step changes and on finish.
- Wizard resume uses `/onboarding` state after remount.
- Dashboard remains mounted/interactive during and after wizard operation.

### Must-NOT-Have
- No second hard-coded solar field list in wizard.
- No empty step shells for Solar/Pricing.
- No blocking modal/wall semantics from Step-2 failure.
- No route or logic changes that add runtime pricing source fetch for Step-3.
